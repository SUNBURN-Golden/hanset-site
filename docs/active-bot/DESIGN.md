# HANSET active collection bot (v1) — design and module contract

Package: `hanset_active/` (repo root, pure Python 3.11+, stdlib + `requests`, `beautifulsoup4`, `lxml`, `Pillow`; system tools `pdftotext` and `tesseract` (kor+eng) are optional at runtime and skipped with a clear status when absent; Playwright/Chromium only for the browser fallback and always imported lazily). CLI: `python -m hanset_active <command>`.
The bot is independent of `site/`, `crawler/` and `data_foundation/`. It never writes site data, CSVs, `site/content/`, or publishes anything. Output = an external SQLite DB + external raw store.

The point of the bot: **it finds new sources and venues by itself**, follows what it collects to the next targets, and re-searches missing fields. A fixed URL list that is re-fetched is NOT this bot. The seed list only defines what is "already known"; the bot reports what it found beyond it.

## Hard rules (enforced in code, covered by tests)
* Never fetch Naver (`naver.com`, `naver.me`, `pstatic.net`, `naver.net`, any `*.naver.*` host) — dropped at candidate creation and again in the fetcher. Instagram hosts are never fetched over HTTP by the bot (only recorded as `sns_link`); the only Instagram code is a connector **stub** (see Connectors).
* Never bypass a block: 401/403/429 challenge pages, captcha/"verify you are human"/Cloudflare "Just a moment"/access-denied pages, robots disallow ⇒ the source/provider is recorded `inaccessible` (with reason) and nothing else is tried for it (no other UA, proxy, account, header spoofing, retry via another route). The User-Agent is an honest identifying one: `HansetActiveBot/1.0 (+mailto:hanset@soulbound.co.kr)`.
* robots.txt is fetched per origin (cached 24 h, through the same rate limiter) and parsed with `urllib.robotparser`; each URL (including every redirect hop) is checked before fetch; `Crawl-delay` > 5 s raises that domain's spacing. robots 404/410 ⇒ allowed; 401/403/5xx/unreachable ⇒ treat as disallowed for this run and record `inaccessible`.
* ≥ 5.0 s between requests to the same domain, 1 in flight per domain (single-threaded executor; domains are interleaved, a global gap of ≥ 1 s also applies). Daily caps (KST day): ≤ 500 new candidate URLs registered, ≤ 200 document bodies fetched (successful or failed HTML/PDF/image/browser fetches; robots/sitemap/feed/API calls are counted in `request_log` and capped at 800/day, not as bodies). Config can only lower caps, never raise them above these.
* PII is stripped before anything is stored: phone numbers (KR formats `010-xxxx-xxxx`, `0x(x)-xxx(x)-xxxx`, `+82 …`, `1xxx-xxxx`, international), **all** e-mail addresses except `hanset@soulbound.co.kr`, tokens/secrets (JWTs, `Bearer …`, `api_key|token|secret|session|sid|auth` query params and assignments, long hex/base64-ish strings ≥ 32 chars), applied to text, quotes, URLs and raw blobs. Replacement markers `[phone]`, `[email]`, `[token]`.
* Never list or output a venue or source matching the exclusion terms `runport`, `런포트`, `butfit`, `버핏` (match on URL, name and body of the candidate; such documents are dropped, not stored). The bot uses the neutral terms "boutique sauna" / "hotel sauna" for venue types and never emits the retired marketing label for them.
* The AI cost cap is 0: there is no model call anywhere. A `ModelHook` interface exists but the only implementation returns `None`. Therefore no `ai_inference` label is ever produced in v1 (the label value exists in the schema). The bot never fills a value by guessing.
* Raw store and DB live outside the repo (`HANSET_ACTIVE_DIR`, default `/workspace/hanset-data/active/`); the code refuses a data dir inside the repo checkout (also via symlink).
* Unknown stays unknown: a value is only stored if a rule matched explicit text; the evidence quote and locator are stored with it.

```

venue_types: [{id: sauna|jjimjilbang|hotel_spa|boutique_sauna|crossfit_box|hyrox_box, ko_terms[], en_terms[], osm_tags[]}]

query_templates: ["{type_term} {region_term}", "{type_term} {region_term} {field_term}", "{region_term} {type_term} {event_term}"]  # event/year terms: 오픈, 이전, 폐업, 요금, 드롭인, 2026
fields: [{id, importance, applies_to[], refresh_days, keywords_ko[], keywords_en[]}]  # see Fields
directories: [{id, kind: osm_search|sitemap|rss|html_list, url, paginate, url_filter, ...}]
relevance_keywords, aggregator_domains (blog/aggregator hosts: tistory, blog.*, brunch, medium, wordpress.com, namu.wiki, tripadvisor, klook, etc.), reservation_platform_domains, sns_domains
exclusion_terms, denied_domains, budgets: {run_requests, run_minutes, class_shares: {backfill: .35, discover: .35, freshness: .30}, discover_floor: .25}
```
Seeds = the venues already known to the repo: names/websites loaded from `saunas.csv`, `boxes.csv` (path configurable) plus origins in `/workspace/hanset-collector/approved_sources.json` (path configurable, optional). `seed` command freezes them into `seed_venues`/`seed_domains` with a `seed_id`; "new venue" = discovered venue whose normalized name (lowercase, strip spaces/punct/branch words, ko+en) AND registrable domain are both absent from the frozen seed. The seed snapshot is never mutated after the first freeze (a new snapshot needs `seed --refreeze`).

## Storage (SQLite, WAL, `PRAGMA foreign_keys=ON`; migrations in `hanset_active/migrations/NNNN_*.sql`, applied idempotently, `schema_version` table)
Four stages plus control tables. All inserts are idempotent (UNIQUE + `INSERT … ON CONFLICT DO NOTHING`/deterministic ids = sha256 of natural key).
1. **raw** `raw_documents(raw_id PK, url, canonical_url, domain, fetched_at, http_status, content_type, content_hash, size_bytes, blob_path, source_id, parent_url, task_id, fetch_method[http|browser|api], extractor_ver_hint, outcome[ok|login_wall|empty_body|blocked|error], UNIQUE(canonical_url, content_hash))` + blob files under `raw/<hh>/<content_hash>`. Blob = PII-stripped normalized text/HTML (for PDF/images: extracted text). `content_hash`: sha256 of PII-stripped normalized main text for HTML (so volatile markup does not create duplicates), sha256 of bytes for PDF/image/feed/json. `fetch_log(url, domain, ts, status, kind, bytes)` for spacing/caps.
2. **extracted** `extractions(extraction_id PK, raw_id FK, extractor, extractor_version, doc_type, lang, title, text_hash, structured JSON(json-ld/tables/headings), mentions JSON(entities: venue/org/place/product-ish names with kind), links JSON(classified: internal|sns|booking|attachment|image_notice|sitemap|next_page), dates JSON, amounts JSON, created_at, UNIQUE(raw_id, extractor, extractor_version))`. Extractors: `html`, `feed` (RSS/Atom/JSON API), `sitemap`, `pdf` (per page text via `pdftotext -layout`, page markers kept; tables kept as layout rows), `ocr` (tesseract `kor+eng`, `--psm 6` then 11 fallback; only for images that look like notices: filename/alt/context keywords price|요금|이용|시간표|timetable|menu|rate, min 400x200), `browser` (Playwright, last resort, only for pages whose HTTP/HTML extraction is an empty app shell; same robots/rate/PII rules; never for blocked/challenge pages). Each extraction stores extractor name + version string constants.
3. **labeled** `labels(label_id PK, raw_id, extraction_id, kind[doc_type|event_type|claim], value, status[fact|source_claim|ai_inference|unverified], rule_id, created_at, UNIQUE(raw_id,kind,value,rule_id))` and `observations(obs_id PK, venue_key, field, value_json, value_text, unit, label_status[fact|source_claim|ai_inference|unverified], source_url, source_type[own_site|official_directory|third_party|aggregator|sns|attachment], quote(≤240 chars, sanitized), locator JSON(selector|char_offsets|pdf_page|ocr_box), raw_id, extraction_id, extractor_version, rule_id, observed_at, UNIQUE(venue_key, field, value_hash, raw_id))`. doc_types: venue_page, price_page, hours_page, rules_page, directory_listing, news_post, event_notice, booking_page, pdf_attachment, image_notice, other. event types: open, relocate, close, price_change, hours_change, closure_notice, collab.
   Label rules (rules first, no model): `fact` = explicit pattern match in an ORIGINAL source (the venue's own domain, an official/public directory, a hotel's own site, an attachment/OCR image hosted on the venue's own domain); `source_claim` = explicit match in a third-party/aggregator/blog page (kept as lead, never a gap-filler); `unverified` = ambiguous (conflicting numbers in one block, negation unclear, only in an image whose OCR confidence < 60); `ai_inference` reserved/unused. "Evidence URL" of a filled gap = the `source_url` of a `fact` observation.
4. **service data** `venues(venue_id PK, venue_key UNIQUE, name, name_ko, type, region, city, website, domains JSON, is_seed INT, seed_match, discovered_via, first_seen_at, state[active|opening_soon|closed|unknown])`, `venue_aliases`, `venue_fields(vf_id PK, venue_id, field, value_json, value_text, unit, label_status, source_url, quote, obs_id, valid_from, valid_to NULL, superseded_by, UNIQUE(venue_id, field, value_hash, valid_from))`, `field_changes(change_id PK, venue_id, field, old_value, new_value, old_obs_id, new_obs_id, detected_at, UNIQUE(venue_id, field, old_value_hash, new_value_hash))`. Venue identity: venue_key = normalized name + region/city; merge only on same registrable domain or exact normalized name+city; branch/vintage/ set vs body are never merged by fuzzy match (store as a `possible_duplicate` review row instead). A changed current value closes the old `venue_fields` row (`valid_to`) and inserts the new one + a `field_changes` row (old and new both kept). A re-observation of the same value is a no-op (maybe bumps `last_confirmed_at` in a separate `confirmations` table, never a duplicate).
Control tables: `sources`, `source_trials`, `tasks`, `gaps`, `gap_attempts`, `review_queue`(conflicts, possible duplicates), `failures` (failure queue), `runs`, `run_checkpoints`, `structure_baselines`, `structure_alerts`, `budgets_daily`, `request_log`, `robots_cache`, `provider_state`, `taxonomy_candidates` (new doc kinds seen, never auto-applied).

## Fields (gap finder vocabulary)
`price_day_pass` (day pass / drop-in / 1회 이용권, KRW amount with unit & ticket scope), `hours`, `closures` (weekly/monthly/dated), `sauna_temp_c`, `cold_bath_temp_c`, `rapid_cold_plunge` (급냉탕: presence yes/no only when text states it), `bath_composition` (list: 건식/습식/온탕/냉탕/열탕/스팀/한증막/아이스배스 …), `tattoo_policy` (allowed/not_allowed/cover_required/conditional), `foreigner_policy` (foreigners accepted / ID / English guide / restrictions). `applies_to`: saunas & jjimjilbang & hotel_spa & boutique_sauna → all nine; crossfit_box/hyrox_box → `price_day_pass`, `hours`, `closures`, `foreigner_policy`. Importance weights (0-1): price_day_pass 1.0, hours .9, closures .7, tattoo_policy .8, foreigner_policy .8, sauna_temp_c .6, cold_bath_temp_c .6, rapid_cold_plunge .5, bath_composition .5.

## Gap finder (`gaps.py`)
For every venue × applicable field one `gaps` row (UNIQUE(venue_id, field)). State machine: `open` → `filled` (a `fact` observation exists, evidence_url stored) | `not_extracted` (an on-domain page is clearly about the field — keyword present within 120 chars of a number/time/Y-N cue or an attachment/image exists — but no rule matched or OCR/PDF is unavailable; remedy = improve extractor/OCR) | `absent_in_source` (≥ 3 distinct relevant on-domain pages incl. EN/KR counterpart and attachments were successfully extracted and none mention the field) | `inaccessible` (all candidate pages blocked/robots/login) | `conflict` (≥ 2 `fact` observations with different values from different sources → `review_queue`). Never fill from AI. Each open gap creates follow-up tasks with strategies tried in order and recorded in `gap_attempts`: `site_links` (internal links whose url/anchor matches the field keywords), `lang_counterpart` (/en/, /ko/, hreflang), `attachments` (pdf), `images` (OCR price/timetable images), `search` (provider queries `"{venue}" {field_kw}`), `directory` (look the venue up in public directories). After all strategies are exhausted the gap gets its final non-open state and is re-opened only by the freshness schedule.

## Discoverer (`discover/`)
Six paths, all bounded by relevance score (keyword/region/type match ≥ threshold), **depth ≤ 2** from the discovery root (root depth 0; search/directory results depth 0, links followed from them +1), per-run request budget, per-domain page cap per run (default 12), candidate dedup by canonical URL (strip tracking params, fragments, trailing slash, lower-case host).
1. `search.py` query combos regions × venue types × language × event/field terms → providers (interface `SearchProvider.search(query, lang, limit) -> list[Hit(url,title,snippet,name,address,website,extra)]`): `nominatim` (OpenStreetMap geocoder API, honest UA, ≤ 1 req/s overall, results of class leisure/amenity/shop/tourism with `extratags.website|contact:website` become **venue candidates with a website** — this is the main discovery path), `wikipedia` (ko/en MediaWiki search API; hits are *leads* with low prior), `brave` (needs `BRAVE_API_KEY` env; absent ⇒ provider state `disabled`, no network), `ddg_html` (`html.duckduckgo.com/html/` — robots allow it; if the response is a bot challenge (HTTP 202 / "anomaly"/"challenge"/"Select all squares") the provider is marked `inaccessible` until next KST day and NOTHING else is tried). Provider failures are recorded in `provider_state` and the run continues with the others. Search result URLs on denied/excluded/aggregator hosts become `source_claim`-grade leads (aggregators registered as `deprioritized` unless evaluator says original).
2. `directories.py` adapters for public/official directories from the profile: `osm_search` (Nominatim by region × type tag/term, paginated via `limit/offset`-style multiple queries), `sitemap` (Korea Tourism EN `https://english.visitkorea.or.kr/sitemap_leisure_sports.xml`, `sitemap_accommodations.xml`, `sitemap_attractions.xml`: URLs are id-style so each URL is an unscored low-prior candidate; the evaluator's trial fetch decides — cap per run), `html_list` with pagination (next link / `?page=N`, max 8 pages), HYROX/CrossFit/other public gym listing pages if robots allow (a 403 from e.g. crossfit.com is recorded `inaccessible`, not bypassed), public bath-business open data portals (record `unreachable`→`inaccessible` after bounded retries if the host cannot be reached).
3. `sitemaps.py` robots `Sitemap:` lines, sitemap indexes (depth-limited, ≤ 20 child sitemaps), RSS/Atom, list pages, pagination (rel=next, `?page=`, `/page/N`, numbered links; repeated cursor/page-hash stops it).
4. `mentions.py` entity mentions in fetched bodies (KO: `<name>(사우나|스파|찜질방|크로스핏|박스|스파앤…)`, EN: `<Name> (Sauna|Spa|Jjimjilbang|Bathhouse|CrossFit|HYROX)` with Title-Case guard, quoted/linked names, JSON-LD names) → normalized, de-duplicated against seed + known venues; unknown ones become `search` tasks (`"{name}" {type_term} {region}`), depth+1, relevance- and budget-limited.
5. `links.py` official site → SNS (instagram/facebook/youtube/kakao/linktree — recorded in `venue_links`, never fetched except by the paused IG connector), booking/reservation pages (non-Naver platforms; Naver booking is recorded as `excluded_link`), attachments (`.pdf`, price/timetable images, with keyword score), EN/KO counterparts, "price/요금/이용안내/FAQ/규정" pages.
6. `reverse.py` gap → tasks (see Gap finder) using the same machinery.
Every discovered candidate stores `discovered_via` (path name + parent URL/task) so acceptance can show provenance.

## Evaluator (`evaluator.py`)
When a new domain/account appears (not yet `registered`/`deprioritized`/`inaccessible`) a `trial` task fetches ≤ 3 pages (landing, the best price/rules/hours-looking internal link, one EN/KO counterpart). Score 0–1 each, stored in `source_trials`:
* relevance: keyword/region/type density in title+main text, venue/organisation name present; 
* novelty: share of extracted entities/fields not already in DB (+ domain absent from seed), minus near-duplicate penalty (5-shingle Jaccard ≥ 0.8 against existing raw text from another domain ⇒ "copy");
* extractability: non-empty main text, a date found, ≥ 1 field observation or table/PDF/attachment, not login/empty/challenge;
* original: own-domain venue name in title/domain/canonical, not an aggregator/blog host, no canonical pointing elsewhere, no "출처/via/원문/repost" markers, not a repost of a known page.
Decision: total = .35 rel + .25 nov + .25 ext + .15 orig; `registered` if total ≥ 0.50 and relevance ≥ 0.4 and extractability > 0; copy-heavy/aggregators ⇒ `deprioritized` (priority multiplier 0.3, still revisited rarely); challenge/robots/blocked ⇒ `inaccessible`. Only `registered` sources get regular crawl, link-following to depth 2 and sitemap expansion. Taxonomy: unseen doc kinds go to `taxonomy_candidates`.

## Executor (`fetcher.py`, `executor.py`, `extract/`)
Lightest first: JSON API / feed → HTML + JSON-LD/microdata → browser only if the HTML main text < 200 chars while scripts/app-root markers exist (and robots allows, not blocked). A response with HTTP 200 that is a login page (password input, "로그인", "sign in" with tiny body), cookie wall only, challenge page, soft-404 ("not found" body) or an empty body (< 80 chars of main text after boilerplate removal) is `outcome=login_wall|empty_body|blocked` ⇒ **failure**, not success: no extraction, goes to failure queue (login_wall/blocked are terminal `inaccessible`, empty_body retries at most once via browser path if applicable). Max redirect 5 (each hop robots-checked, same-host or still allowed), response ≤ 2 MB (PDF ≤ 8 MB, image ≤ 4 MB), connect/read timeout 15 s, `Accept-Encoding: gzip`. Each result stores content hash, fetch time (KST ISO), extractor version, `source_ref` = (parent_url, task_id, discovered_via).
Rule extraction (`extract/fields.py`): bilingual regex rules, each with `rule_id` and version; they extract only from sanitized text/table cells/OCR text/PDF pages and return value + quote + locator. Examples to cover: KRW amounts (`₩25,000`, `25,000원`, `25000 KRW`, `2만5천원`, `만원`) near `요금|이용료|입장료|1회|일일|drop-in|day pass|visit`; hours `HH:MM ~ HH:MM`, `24시간`, `연중무휴` with weekday/weekend scope; closures `매주 화요일 휴무`, `매월 첫째 주 월요일`, `closed on Mondays`, date ranges; temperatures `80~100℃`, `90°C`, `섭씨` near `사우나|핀란드식|건식|sauna` vs `냉탕|냉수|cold plunge|ice bath|아이스` (separate fields), `급냉탕` presence; bath composition keyword set; tattoo `문신 (불가|금지|가능|허용|커버|스티커)` / `tattoo(s) (not allowed|allowed|must be covered)`; foreigners `외국인|foreigner|English|tourist|passport|ID`. Negation/uncertainty handled; no match ⇒ no value.

## Scheduler (`scheduler.py`)
Task classes: `backfill` (lists/pagination/archives/missing page ranges, gap follow-ups for never-filled gaps, sitemap expansion of registered sources), `discover` (search/directory/mention/link/trial tasks), `freshness` (revisit known pages, changes/deletions). Per-run request budget is split by `class_shares`, **discover keeps ≥ 25 % even when freshness has stale items**; unused share flows to the others. Task score = `w_n·novelty + w_g·gap_importance + w_u·urgency + w_q·source_quality − w_c·cost − w_d·duplication − w_f·repeat_failures` (weights in profile; defaults .30/.25/.20/.10/.05/.05/.05 scale). `urgency` = staleness / refresh interval; refresh intervals: `price_day_pass`, `hours`, `closures` **3 days** (short), temps/bath/policy 14 days, identity/links 30 days, deprioritized sources 30 days. Dedup via `tasks.dedupe_key UNIQUE`. The picker skips tasks whose domain is in cool-down and takes the next best ready one, sleeping only if nothing is ready (bounded by run time budget).

## Reliability (`runner.py`, `locks.py`)
* Overlap lock: `fcntl.flock` on `<data>/run.lock` plus a DB `run_lease` with heartbeat; a second run exits 0 with `already_running`.
* Checkpoints/resume: each task executes in short transactions; `tasks.state` `pending→running(lease_until)→done|failed|dead`; on start, `running` tasks with expired lease go back to `pending` (their raw/extraction inserts are idempotent so no duplicates); `run_checkpoints` store pagination cursors/sitemap positions/search offsets so a resumed run continues after the last successful item. `SIGTERM` finishes the current task and stops cleanly.
* Bounded retries: ≤ 3 attempts, backoff 10 min / 1 h / 6 h (`next_at`), then `dead` in `failures`. 429 ⇒ honour Retry-After and stop the domain for the run; blocks ⇒ `inaccessible`, no retry.
* Structure-change detection: per source template signature (hash of the tag-path skeleton of the main content + the set of field ids extracted from a page type). If a page type that extracted ≥ 1 field before now extracts 0 (or the signature Jaccard similarity to baseline < 0.5), write a `structure_alerts` row and mark the gap/source `needs_extractor_review`, do not treat it as "absent_in_source".
* Idempotent reruns: re-running the same pages produces 0 new rows in raw/extractions/labels/observations/venue_fields/field_changes/gaps (UNIQUE constraints; `report` has a `duplicate_check` section that counts duplicate natural keys and must be 0).

## Tests (`tests/active_bot/`, pytest, offline)
A threaded local HTTP fixture server with de-identified fixtures (`tests/active_bot/fixtures/`): venue pages KO+EN with prices/hours/temps/tattoo/foreigner text; a multi-page list with `rel=next`; sitemap index; RSS; JSON API; a PDF with text; an image with a price table (generated with Pillow, English digits so `eng` OCR works); login page returning 200; empty body 200; a "Just a moment" challenge page; robots.txt with Disallow; a page whose markup changes between passes; a page whose price changes between passes; a Naver URL; an excluded-term page; pages containing phone/email/token strings. Tests inject a fake clock and `min_interval=0` for speed but assert the production defaults are 5.0 s, 1/domain, 500/200 caps. Required test groups: pii, fetcher (robots, rate spacing with fake clock, caps, redirects, block/login/empty ⇒ failure, naver/IG denied), extractors (html, jsonld, feed, sitemap, pdf, ocr, browser fallback decision logic), fields/labels (each field, negation, third-party ⇒ source_claim, never ai_inference), discoverer (each of the 6 paths yields tasks beyond the seed; depth ≤ 2; budget stop), evaluator (register/deprioritize/inaccessible; copy detection), gaps (each final state, reverse-search follow-ups), scheduler (budget split, discover floor, urgency, freshness intervals), service data (changed value old vs new; same value no-op), reliability (resume after injected crash, overlap lock, retries → dead, structure-change alert, idempotent rerun with 0 duplicates), IG stub paused.
